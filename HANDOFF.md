# Material Email handoff

## Current state

Material Email is an unreleased Windows-only Electron foundation. Main-process and preload services exist for IMAP/SMTP accounts, advisory autoconfiguration, queued offline changes and an outbox, attachment saving, demo data, local drafts, notifications, history, exports, native custom-editor approval, and window controls. A bounded local unified-folder slice aggregates cached Inbox, Starred, and Unread summaries across configured accounts, labels every row with its source account, reuses the mail regex builder, and preserves composite selection through deterministic refreshes. Visible cached rows now receive bounded in-memory conversation grouping from normalized subject plus cached `Message-ID`/`In-Reply-To`/`References`; grouping stops above 2,000 rows and leaves them individually accessible. It performs no all-account server pass and claims no server-complete threading or scalable mail index. MIME parsing, conservative message-HTML sanitization, and an isolated reader boundary are present. Packaged builds ignore `MATERIAL_EMAIL_DEV_URL`; unpackaged development accepts only strict HTTP loopback URLs at `127.0.0.1` or `[::1]`. Every IPC handler authenticates the current main window's `WebContents`, its top frame, and the exact trusted renderer URL/path. The renderer now contains Mail, Contacts, Mailing Lists, Calendar, Tasks, PIM Transaction History, Settings, Changelog, History, Notifications, and Tools/About panels plus first-run setup, non-modal compose, and structured local-organizer editors. History now has an independently searchable whole-workspace revision list, bounded parent diff previews, local Git-note labels, reviewed whole-state restore, persisted 30–3,650-day retention with exact dry-run preview, and a read-only deletion-evidence report. Apply prunes only app-owned eligible revisions after stale-head and clean-lineage checks, preserves the current tree and labels, and appends a semantic event. Inspection reports active/labeled/reflog-only revisions and Git object inventory while explicitly recording that it performs no cryptographic erasure, reflog expiry, garbage collection, backup audit, or media audit. Object reclamation, crash-injection coverage, cryptographic-erasure design, and every-record restore are not complete. Workspace tabs have a focused per-element appearance slice: validated local overrides for color, type size/weight, and radius; context-menu and direct keyboard entry; independent property reset; restart persistence; and exact focus return. Their primary tab strip also keeps focus on the selected tab during Arrow/Home/End navigation, exposes one roving tab stop with reciprocal tab/tabpanel IDs, and renders a tested inset keyboard focus indicator. This does not claim the broader Word-depth every-element editor, native screen-reader certification, or the full display-scale matrix. Packaged visual/accessibility proof remains incomplete.

Valid mail queries now build an ephemeral main-process index over at most 2,000 coherent cached summaries and 4,096 already-cached body characters per row. Plain and regex modes share the builder validator, results cap at 200, and each hit carries account, folder, conversation, matched-field, and snippet attribution. This is query-time local work, not SQLite, persistent full-text search, background indexing, server search, or large-store proof.

Message cryptography now has a bounded metadata-only trust-state foundation. A strict version-1 account profile accepts at most 16 public OpenPGP/S/MIME identity records and rejects unknown fields, plaintext secrets, private material, secret references, and verified claims. Message detail parsing inspects only the bounded top-level MIME header and records `unsigned`, `unverified`, or `unsupported` plus literal facts that signature verification and content decryption were not performed. The reader and compose surfaces expose accessible English/Cantonese/bilingual indicators; compose always says the current SMTP path sends unsigned and offers no sign/encrypt action. Focused evidence is 3 unit/parser/persistence files / 29 tests and 1 / 1 real-Electron scenario. No signature, encryption, decryption, verification, key/certificate import, audited crypto library, or provider interoperability exists.

Account setup now runs one shared deterministic preflight over both IMAP and SMTP settings before the mail service can open a transport. It rejects non-host syntax and certificate wildcard patterns, conventional implicit-TLS/STARTTLS port inversions, and invalid ports; IP literals, private/single-label names, custom secure ports, and explicit plain transport receive factual advisories. The bilingual live region marks blocking controls with `aria-invalid`, switches to an assertive alert on submit, focuses the first invalid field, and states that no server was contacted. The main process repeats blocking checks before connection, encryption, or persistence. Focused evidence is 2 unit files / 8 tests and 1 / 1 real-Electron scenario. No server certificate was inspected: certificate chain/trust/expiry/revocation/interception, an observed hostname mismatch, live provider/proxy/IPv6 behavior, and interoperability remain unproved.

An optional incoming/outgoing action can now inspect a live certificate only after the user presses it. The credential-free IPC contains endpoint, host, port, and security mode only. Direct TLS or fixed IMAP/SMTP STARTTLS negotiation shares one five-second deadline; response bytes cap at 16 KiB and displayed chains at eight certificates. Renderer output includes runtime trust, hostname match, protocol/cipher, validity, key type/size, completeness, and short one-way IDs while raw names, SANs, serials, full fingerprints, certificate bytes, and greetings remain undisplayed and unpersisted. Plain mode opens no socket. Focused evidence is 2 unit/IPC files / 15 tests and 1 / 1 real-Electron loopback scenario proving zero connections before the explicit click. This does not prove provider login or interoperability, revocation/CT status, interception, proxy behavior, or IPv6 connectivity.

OAuth account setup now has an ephemeral authorization-code/PKCE foundation instead of a pasted-token field. A configured attempt generates fresh 64-byte verifier and 32-byte state entropy, binds an exclusive ephemeral `127.0.0.1` listener, opens the authorization URL only from the main process, and accepts only the exact GET peer/host/port/path/state with one bounded code or provider error. Renderer IPC exposes status only. Authorization receipt, cancel, five-minute timeout, provider denial/error, browser/listener failure, and repeated invalid callbacks close the listener and zero/clear temporary state. The code is discarded; there is no token exchange, token persistence/logging, provider registration in production, or connected OAuth account. The main service rejects OAuth-labeled test/add requests before mail transport or persistence. Focused evidence is 8 OAuth unit tests, 29 / 29 combined IPC/security assertions, and 1 / 1 real-Electron scenario covering bilingual semantics, no token-entry path, waiting/cancel status, polling focus, and a 760 × 560 viewport. No live provider authorization or token behavior is claimed.

A separate `oauth-token-vault.ts` now provides the production main-process Windows storage boundary. Initial save and rotation require an explicit bounded provider registration; the shipped registration and revoker lists are empty. Access and refresh values are independently protected by Electron `safeStorage`, replacement uses a synchronized same-directory temporary file, rotation increments a bounded metadata generation and preserves the existing refresh ciphertext when a provider omits a new value. Provider-level clear removes active local ciphertext without claiming secure filesystem erasure. An injected registered revoker can receive decrypted tokens only inside the main process, and local ciphertext is still cleared when that call fails. Renderer IPC exposes only protection/failure state, provider registration, count, generation, expiry, and action availability. Five focused vault unit tests run with a test-only provider source; the real-Electron Settings scenario verifies bilingual accessible status, disabled production actions, no token input/key, and the 760 × 560 bound. No live exchange, provider revocation, connected account, or interoperability is claimed.

`mock-oauth-token-lifecycle.ts` continues to model exchange, expiry, refresh rotation, and revocation for tests and explicitly constructed demo harnesses only. It is not imported by production main, preload, IPC, `AppService`, or the visible demo workspace. Its ephemeral vault stores AES-256-GCM ciphertext in memory, authenticates each record against its storage key, clears replaced/deleted blobs, and zeros its process-local key on disposal. Six focused tests cover ciphertext inspection, exchange/expiry/refresh/revoke, revocation-failure deletion, invalid input/transitions, and explicit demo construction. These mock values are not provider credentials or token-lifecycle interoperability evidence.

Account setup now exposes a bounded POP3 foundation beside the existing IMAP path. Strict options cover local-demo versus explicitly unsupported live-network mode, new-only retrieval, required leave-on-server, and a `1..50` message limit; local diagnostics use conventional ports `995`/`110`. The bilingual panel disables live account and credential controls, then runs deterministic fixtures through `idle → connecting → authorization → transaction → update → disconnected`. Main-process test/add also refuse POP3 before mail transport, encryption, or persistence. Focused evidence is 5 files / 33 tests plus 1 / 1 real-Electron scenario. No live server, provider capability, login, TLS handshake, durable UIDL state, polling, retention, `DELE`, or full synchronization is claimed.

The command palette now uses the same independent plain-text-first search model and adjacent bounded JavaScript-regex builder as the audited Settings, semantic and whole-workspace History, Notifications, and Tab Manager fields. It matches the visible English and Cantonese command labels, exposes invalid regex state, returns no executable result for invalid or risky patterns, and limits <kbd>Enter</kbd> activation to its search input. <kbd>Escape</kbd> closes the nested builder before dismissing the palette. This focused slice does not close the broader every-surface, Unicode, multiline, adversarial-timeout, assistive-technology, or display-scale matrices.

Raw MIME now passes through one main-process safety policy before detail or attachment parsing. A new parse with a known server size above 32 MiB is refused before the mail service runs; IMAP source requests cap the returned range at 32 MiB plus one detection byte. The parser also rejects header blocks above 64 KiB, physical header lines above 8 KiB, header NUL bytes, decoded text above 2 MiB, decoded HTML above 4 MiB, more than 100 attachments, one decoded attachment above 20 MiB, or decoded attachments above 24 MiB combined. CID links are kept as links and synthesized text-to-HTML output is disabled to avoid needless in-memory amplification. Stable failures omit parser internals, leave the cache and message unchanged, and flow through the existing non-modal reader error with safe retry guidance. This is a local bounded-parser slice, not live-provider interoperability, a comprehensive malformed corpus, a parser hard timeout, or antivirus analysis.

A PIM service under `src/main/pim/` covers contacts, mailing lists, bounded vCard import/export, a local Home calendar, events, tasks, append-only transactions, generation recovery, cross-instance/process locking, and stale-refresh protection. It is integrated through typed preload/IPC operations and Material renderer pages. A separate provider foundation validates CardDAV/CalDAV HTTPS profiles and absolute local Windows ICS file URLs, rejects URL credentials/query/fragment data, records auth mode without accepting a secret, follows a deterministic `idle → validating → capability-review → ready` or `rejected` trace, and reports only bounded local vCard/iCalendar envelope capabilities. Interchange inspection caps input at 1 MiB / 20,000 lines / 8,192 bytes per line, requires balanced vCard 3/4 or iCalendar 2.0 components, refuses scheduling `METHOD` and attachments, and counts recurrence rules without expanding them. No DNS, socket, TLS, provider discovery/login, credential storage, read/write, ETag, sync-token, scheduling, file watching, persistence, live synchronization, or provider interoperability is claimed.

Mail mutation handling now treats false IMAP results as failures, refuses unsafe copy/delete fallback on servers without MOVE, adopts the server-returned destination UID and UIDVALIDITY without recycling the source UID, and waits for refresh when an offline or unmapped destination cannot be updated authoritatively. A permanent all-recipient SMTP 5xx returns the exact rejected recipients and keeps the draft rather than entering an outbox retry. Removing an account purges its live cache, drafts, outbox entries, and pending operations while append-only history remains available.

External message links now use a deny-by-default review flow. Electron denies every popup, the main process keeps only a short-lived single-use opaque request, and the trusted renderer shows a bilingual confirmation with the normalized URL, hostname, risk, and factual warning reasons. Confirmation revalidates expiry and HTTP(S) protocol before `shell.openExternal`; cancellation, expiry, duplicate use, and browser-launch failures do not open the link.

Remote HTML images now use a separate default-deny, per-message consent flow. The main-process sanitizer keeps the ordinary reader HTML image-free and builds a second bounded variant containing only normalized absolute HTTP(S) images plus their origin/host/protocol summary. The reader lists those exact origins in accessible English, Hong Kong Cantonese, or bilingual copy before loading anything. Consent is persisted on the cached message, survives restart, can be revoked, and resets when a new mailbox generation replaces the cached detail. The application CSP is unchanged; a consented opaque message frame adds only those origins to `img-src` while scripts, forms, frames, objects, media, connections, referrers, and same-origin access stay denied. HTTP receives a transport warning, not a certificate diagnostic.

Caution and dangerous received attachments now enter local quarantine before any user-selected save destination. The main process stores bytes under randomized `.quarantine` names and persists original metadata, source UID/UIDVALIDITY provenance, risk reasons, byte size, timestamp, and SHA-256 integrity. The Tools panel provides keyboard-accessible English, playful Hong Kong-style Cantonese, and bilingual Release/Delete decisions. Release rechecks size/hash and uses a native destination dialog; delete never releases a copy. Ordinary batch members still use the native folder chooser. This is not antivirus scanning, and no malware-clean verdict is produced.

Compose and PIM editors use saved/loaded dirty baselines. Their discard decision is accessible and restores focus, replacement attempts are guarded, and the unload guard covers either dirty editor so a whole-window close cannot silently discard the form. Send/Save operations are mutually exclusive; edits made during an in-flight operation remain visible and unsaved, while the main process preserves newer same-ID draft versions. PIM saves are bound to their originating editor and keep a retryable, factual state if post-save refresh fails. Mail account/folder/message requests use monotonic ownership so late results cannot overwrite the current view.

No hosted documentation site or clean-machine installation proof exists at this handoff. Published installers exist, and a new local verifier now proves a strict prior-release-to-candidate upgrade without confusing that evidence with clean-machine certification. The release workflow is wired to download the latest prior installer and require the same upgrade evidence before its next publication; that updated hosted gate has not run yet.

## Security facts

- Renderer sandboxing, context isolation, disabled Node integration, navigation denial, and permission denial are configured.
- Message popups are denied; external HTTP(S) links require a trusted-renderer confirmation request with bounded opaque IDs, 60-second expiry, single-use consumption, and protocol revalidation before browser launch.
- Packaged renderer startup ignores the development URL environment variable; unpackaged development permits only exact HTTP loopback hosts.
- Every IPC operation authenticates the current main `WebContents`, top frame, and exact trusted renderer URL/path before validating its bounded payload.
- Account secrets are encrypted through Electron `safeStorage` before JSON persistence and omitted from public account summaries.
- New OAuth attempts keep URL/state/verifier/code in ephemeral main-process memory, expose only bounded status IPC, zero/clear attempt buffers on every terminal path, call no token endpoint, and write nothing to account state, history, notifications, or logs. Production provider registration is empty and OAuth-labeled account add/test requests are refused.
- The Windows OAuth vault requires an explicit provider registration before token writes, uses `safeStorage` only in the main process, writes ciphertext plus bounded metadata atomically, exposes no token/ciphertext/account/scope through IPC, and permits local clear independently from provider availability. Production provider/revoker lists remain empty.
- The mock token lifecycle is isolated test/demo code with no filesystem, network, IPC, or logging route. Its ephemeral AES-GCM vault is not durable Windows protection and is not imported by the production vault.
- Message HTML is allowlisted. Its default document removes images; its separate consent variant retains only normalized HTTP(S) images and loads exact listed origins after a persisted per-message decision.
- Raw MIME reads and decoded parser output have fixed local safety ceilings; refusal leaves message/cache state unchanged and does not expose parser internals.
- OpenPGP/S/MIME handling is metadata-only: bounded top-level MIME labels can produce unsigned, unverified, or unsupported states, but no signature or sender is verified and no content is decrypted. Identity profiles reject keys, passphrases, secret references, and verified claims before persistence.
- State writes use a same-directory temporary file and rename and serialize concurrent updates.

Open security work includes live-provider certificate revocation/CT/interception and interoperability matrices, broader IPC payload testing, live-server remote-image failure coverage, antivirus/content scanning and reputation integration, OAuth provider registration/code exchange/provider refresh and revocation/scope review/account authentication, vault migration/recovery testing, audited cryptographic messaging and key lifecycle, and PIM at-rest encryption decisions. The bounded message-cryptography trust-state metadata, OAuth PKCE/loopback state machine, Windows vault adapter, local connection preflight, explicit redacted live inspection, and safe-link review are implemented; none is cryptographic or provider interoperability evidence.
